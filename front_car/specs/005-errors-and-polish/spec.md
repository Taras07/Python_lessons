# Ітерація 005: Обробка помилок API і полірування стилю

## Мета ітерації

Показувати користувачу зрозумілі повідомлення про помилки бекенду та довести інтерфейс каталогу автомобілів до охайного вигляду без зміни функціональної логіки попередніх ітерацій.

## Що вже є

Функціональність ітерацій 001–004:
- Список автомобілів.
- Фільтрація за доступністю та мінімальним рейтингом, а також за іншими передбаченими фільтрами.
- Пагінація списку.
- Створення автомобіля.
- Редагування автомобіля.
- Видалення автомобіля.

## Що додаємо

- Єдине місце показу помилок в інтерфейсі: інформаційний блок (banner) у верхній частині сторінки. Він автоматично приховується після наступної успішної дії.
- Обробку кодів відповіді API:
  - `409 Conflict` (POST або PATCH) → «Автомобіль із таким VIN уже існує».
  - `404 Not Found` (PATCH, DELETE або повторний запит) → «Автомобіль не знайдено. Можливо, його вже видалено».
  - `422 Unprocessable Entity` → «Перевірте правильність заповнення форми».
  - Мережева помилка (fetch кидає виняток) → «Не вдалося з'єднатися із сервером. Перевірте, чи запущений бекенд».
  - Інші помилки сервера → «Сталася помилка під час виконання запиту. Спробуйте ще раз».
- Візуальне полірування `style.css`:
  - Картки автомобілів розташовані в адаптивній сітці (`grid`).
  - Кнопки «Додати автомобіль», «Редагувати», «Видалити», «Застосувати», «Назад» і «Далі» мають узгоджений стиль та стани наведення (`hover`).
  - Поля форм, фільтри, модальні вікна та інформаційні повідомлення оформлені в єдиному стилі.
  - Кольорова схема забезпечує достатній контраст і читабельність тексту.
  - Інтерфейс коректно відображається на різних розмірах екрана.

## Явно поза межами цієї ітерації

- Нову функціональність, нові поля та нові ендпоїнти НЕ додавати.
- Не змінювати бізнес-логіку бекенду та правила валідації даних.
- Не змінювати HTML-структуру та JavaScript-логіку, якщо це не потрібно для показу помилок або стилізації інтерфейсу.
- Не додавати авторизацію, реєстрацію користувачів чи інші нові можливості.

## Критерії приймання

- [ ] Помилка `409` під час створення або редагування показує повідомлення про автомобіль із таким VIN.
- [ ] Помилка `404` під час редагування або видалення показує повідомлення, що автомобіль не знайдено.
- [ ] Помилка `422` показує повідомлення про неправильне заповнення форми.
- [ ] Мережева помилка показує повідомлення про неможливість з'єднання із сервером.
- [ ] Інші помилки API не залишаються без повідомлення для користувача.
- [ ] Інформаційний блок із помилкою приховується після наступної успішної дії.
- [ ] Картки автомобілів відображаються в адаптивній сітці.
- [ ] Кнопки мають узгоджене оформлення та видимий стан `hover`.
- [ ] Форми, фільтри, модальні вікна та пагінація мають єдиний візуальний стиль.
- [ ] Уся функціональність ітерацій 001–004 продовжує працювати без регресій.
